# 🛸 Text Quest Game Application

Цей проєкт — вебзастосунок на базі Java-сервлетів, реалізований у форматі текстового квесту. Гравець крок за кроком 
приймає рішення та керує розвитком сюжету, а сама гра динамічно підтягує ігрові сценарії з JSON-файлу. Логіка застосунку
ізольована за допомогою HTTP-сесій, що дозволяє багатьом користувачам грати одночасно без конфліктів даних.

## 🛠️ Стек технологій
* **Java:** JDK 17
* **Вебконтейнер:** Apache Tomcat 10.1.18 (специфікація Jakarta EE 10)
* **Збирання проєкту:** Maven
* **Бібліотеки:**
    * Jackson Databind (для роботи з JSON)
    * Lombok (для генерації бойлерплейт-коду)
* **Тестування та якість:**
    * JUnit 5 & Mockito
    * SonarQube for IDE / SonarLint (аналіз якості)

---

## 🏗️ Архітектура проєкту

Застосунок побудовано за класичною трирівневою архітектурою:
1. **Web Layer (`QuestServlet`):** Обробляє HTTP GET/POST запити, керує станом гри в сесії користувача (`isStarted`, `questService`) та перенаправляє на сторінки відображення (`index.jsp`, `quest.jsp`).
2. **Service Layer (`QuestService` / `QuestServiceImpl`):** Містить чисту бізнес-логіку квесту (перевірка валідності відповідей, здійснення кроку, скидання прогресу).
3. **DataAccess Layer (`QuestRepository`):** Відповідає за зчитування JSON-структури з файлу ресурсів (`quest.json`) за допомогою Jackson та мапінгу її в немодифіковану колекцію (`toUnmodifiableMap`).

---

## 🧪 Тестування та якість коду

Проєкт покритий Unit-тестами з використанням **JUnit 5** та **Mockito**:
* **`QuestServiceImplTest`**: Перевіряє життєвий цикл сервісу, правильність переходів між кроками та валідацію винятків (`IllegalArgumentException`, `IllegalStateException`).
* **`QuestRepositoryTest`**: Інтеграційні тести, що перевіряють парсинг валідного JSON, обробку битих файлів та реакцію на відсутність файлу в ресурсах за допомогою кастомного винятку `QuestDataException`.
* **`QuestServletTest`**: Повністю ізольовані тести вебшару. Використовують Mock-об'єкти сервлетного API (`HttpServletRequest`, `HttpSession`, `HttpServletResponse`) та Java Reflection API для безпечного впровадження mock-залежностей у приватні поля.
 
  Код застосунку успішно проаналізовано за допомогою **SonarQube**, що гарантує відсутність критичних архітектурних помилок, багів та вразливостей. Загальне покриття тестами (Code Coverage) відповідно до звітів **JaCoCo** становить **95%**.

## 🚀 Інструкція із запуску проєкту

1. **Встановіть необхідне програмне забезпечення:**
    * Java Development Kit (JDK) 17 або новішої версії.
    * Apache Maven.
    * Apache Tomcat 10.1.18.

2. **Клонуйте проєкт:**
   Форкніть та клонуйте цей проєкт із репозиторію GitHub на свій локальний комп'ютер.

3. **Запустіть застосунок:**
   Відкрийте проєкт у вашій IDE (наприклад, IntelliJ IDEA), налаштуйте локальний сервер Tomcat 10.1.18 та запустіть його.
